Design document · repo quicknote · 25 Oct 2026

Quicknote: a free Kippy-style capture app for macOS

Reference: heykippy.app and its v1.0 changelog Price: free (no licensing)

Context and problem

Kippy is an unreleased, macOS-only capture app. A small tab on the right edge of the screen and a set of ⌃⌥ shortcuts capture typed notes, voice, screenshots and meetings over any app. It sorts each entry into a task, reminder or event, then brings it back at the due time or when you switch to the app or site it belongs to. Everything runs on the Mac: no account, no cloud, no cloud AI. The goal here is to build an app with the same feature set and give it away for free. quicknote is the working name until branding is settled.

Goals and non-goals

Goals

  • Match every feature listed on Kippy's site and v1.0 changelog (the feature map lists each one).
  • Fully offline and on-device: no server, no account, no analytics. Capture, search and reminders work with Wi-Fi off.
  • Match Kippy's macOS 14 Sonoma minimum, on Apple silicon and Intel.
  • Your data stays yours: export any note as Markdown, keep attachments as plain files, and delete everything with one button.

Non-goals

  • Payments, licensing, trial and device limits. This is freeware.
  • iOS, Windows, web, or cloud sync. Kippy has none of these.
  • Languages other than English for voice and read-aloud in v1, same as Kippy. Typed notes work in any language.
  • Copying Kippy's name, brand, artwork or marketing copy. Features are fair game; the identity must be our own.
  • A marketing site and waitlist. One static page can come later.

Options considered

Almost every feature depends on a macOS system API: global hotkeys, floating non-activating panels, Accessibility, ScreenCaptureKit, Core Audio, Speech, EventKit and notifications. The main question is how directly the stack reaches them.

A. Native Swift chosen

  • SwiftUI for views, AppKit for panels, the edge window and the text editor.
  • Every system API is called directly with no bridge.
  • Low memory use, which matters for an app that is always running.
  • Costs: macOS only, and AppKit gaps need hand-written code (rich text editing, overlay windows).

B. Tauri 2

  • Rust core with a web UI, so the UI could later be reused on Windows.
  • Each OS feature still needs a Swift or Objective-C plugin, so you write native code plus a bridge.
  • Floating panels over fullscreen apps and a click-through edge window are hard to build in a webview.

C. Electron

  • Fastest path for web developers, with the largest ecosystem.
  • Same native-module problem as Tauri, plus a full Chromium running in the background all day.
  • Out of step with a "small Mac app" that runs offline.

Decision

Build a native Swift app with a SwiftUI and AppKit hybrid, targeting macOS 14+. Use GRDB with FTS5 for storage, Apple Speech for transcription, ScreenCaptureKit for Snap, Core Audio taps for meeting audio, EventKit for Calendar, and UNUserNotificationCenter for reminders. Sparkle handles updates. The only third-party packages are GRDB, KeyboardShortcuts and Sparkle.

Kippy is Mac-only and almost every feature is an OS integration, so a cross-platform UI layer adds a bridge without adding reach.

Changed from the original brief: licensing, the 7-day trial, pricing and the 3-Mac limit are removed because the app is free. Sparkle stays, since a free app still needs updates.

Core interfaces

// Sorting/EntryClassifier.swift: pure, unit-tested
struct Classification: Equatable {
    var kind: NoteKind            // .note .task .reminder .event .todoList .idea .bookmark .bug .context
    var due: Date?
    var hasTime: Bool
    var recurrence: RecurrenceRule?
}
enum EntryClassifier {
    static func classify(_ text: String, now: Date, calendar: Calendar) -> Classification
}

// Voice/Transcriber.swift: one type, picks the engine by OS version
final class Transcriber {
    func start() throws -> AsyncStream<TranscriptSegment>   // live partials for the panel
    func finish() async throws -> [TranscriptSegment]         // segments with start and end in ms
}

// Canvas/CanvasDocument.swift: shared by Snap and Cards, saved as JSON
struct CanvasDocument: Codable {
    var background: CanvasBackground   // .image(attachmentID) for Snap, .card(CardStyle, CardSize) for Cards
    var elements: [CanvasElement]      // shape, arrow, text, step, highlight, blur, sticker, photo, washi, ink
}
struct CanvasElement: Codable, Identifiable {
    var id: UUID; var kind: Kind; var frame: CGRect; var rotation: Double; var style: ElementStyle
}

Meeting action item to task

MeetingRecorder mixes microphone and tap audio into one .m4a. Segments stream into transcript_segment. ⌃⌥B stores a meeting_bookmark at the current offset. When recording stops, ActionItemExtractor scans the segments for phrases ("action item", "I'll", "we need to", "by Friday") and turns each hit into a task with source_meeting_id and source_ms. Opening the task seeks the player to that second.

Testing and verification

Logic that decides something (dates, repeats, formatting, links, search, export, action items) lives in pure functions or works against an in-memory GRDB queue. Those get unit tests written first. Features behind a permission prompt are checked by hand against a fixed checklist in each PR.

Manual checklist for each permission-bound feature: grant, deny, and revoke while running. Run it with Wi-Fi off (offline claim), on two displays, over a fullscreen app, and on one Intel Mac.

Risks and mitigations

RiskMitigation
Browser URL through Accessibility is unreliable. Chrome may not expose AXWebArea until its accessibility is enabled (forum).Spike first in M3. Fall back to Apple Events per browser. Site notes degrade to app-level notes if both fail.
System audio taps record silence when NSAudioCaptureUsageDescription is missing, and there is no public API to check the permission (recall.ai).Check the plist key in a unit test. Detect a silent tap in the first 3 seconds and show a fix-it banner.
On-device SFSpeechRecognizer is less accurate and can fail with "No asset installed" until language assets download.Use SpeechAnalyzer on macOS 26. Check supportsOnDeviceRecognition at first launch and prompt for the asset download.
Rule-based sorting picks the wrong type.Show the type chip before saving, allow a one-key change, and always confirm before writing to Calendar.
Default ⌃⌥ shortcuts clash with other apps.The KeyboardShortcuts recorder warns about conflicts. All shortcuts can be changed.
The edge window misbehaves with Spaces, fullscreen apps, or displays being plugged and unplugged.Rebuild the edge windows on NSApplication.didChangeScreenParametersNotification. Fullscreen is on the manual checklist.
Notarization needs a paid Apple Developer Program membership, even for freeware.Budget for it before M9.

Open questions

  1. Minimum macOS 14 or 26? Raising it to 26 drops the SFSpeechRecognizer path and makes Foundation Models available for sorting and meeting summaries, but excludes Macs still on 14 or 15. Kippy targets 14, so this doc does too.
  2. Meetings: microphone only, or system audio too? Kippy lists only Microphone among its permissions, which suggests it may record only the mic. That loses remote participants when you wear headphones. This doc plans for both.
  3. What does "search files" cover? Attachments and Snaps only (planned), or files anywhere on disk through Spotlight (NSMetadataQuery)?
  4. "Greets you when you return": return from what? This doc assumes wake, unlock and launch. It could mean switching back to the app where you saved the context.
  5. Calendar access level. Kippy describes Calendar as add-only, yet its Daily Brief shows today's events, which needs full access. Should we ask for full access up front or only when the Brief is turned on?
  6. Slack in the share sheet. Unverified whether Slack's Mac app registers as an NSSharingService.
  7. Name and visual identity. "Quicknote" is a placeholder.

Alternatives rejected

  • Tauri 2: every OS feature still needs a native plugin, so it adds a bridge without adding reach.
  • Electron: a background Chromium all day in an app that should feel tiny.
  • SwiftData: no full-text search API was found to match GRDB's FTS5 support. unverified
  • WhisperKit: large model download and unknown speed on Intel. It remains the upgrade if Apple Speech accuracy is not good enough for meetings.
  • Cloud LLM for sorting and summaries: breaks the no-cloud promise.
  • Mac App Store: the sandbox blocks Accessibility, which app notes need.
  • Separate canvases for Snap and Cards: both need move, resize, rotate and voice text, so one canvas serves both.
